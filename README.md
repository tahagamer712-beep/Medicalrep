# نظام إدارة شركات الأدوية والمندوبين الطبيين
# Medical Representative Management System

نظام متعدد الشركات والمكاتب لإدارة المندوبين الطبيين — يعمل من الهاتف (Termux)
ويمكن نقله لاحقًا إلى خادم دائم.

## المكونات

| المكوّن | الحالة |
|---|---|
| نواة النظام (هوية/صلاحيات/عزل) | ✅ مكتمل ومُختبَر |
| خطط/زيارات/حضور/تذكيرات | ✅ مكتمل ومُختبَر |
| إجازات/اجتماعات/استبيانات/منتجات/ملف طبيب | ✅ مكتمل ومُختبَر |
| المالية (رواتب/خصومات/مكافآت) | ✅ مكتمل ومُختبَر |
| التقارير + Excel/CSV + استيراد Excel للأطباء | ✅ مكتمل ومُختبَر |
| بوت Telegram للـ Owner (قراءة + إجراءات كتابة) | ✅ مربوط بالخدمات، مختبر بـ mocks (لم يُجرَّب حقيقيًا) |
| بوت WhatsApp | مؤجل — مرحلة مستقلة لاحقًا |
| النسخ الاحتياطي المشفّر (مكاتب + هوية) والاستعادة | ✅ مكتمل ومُختبَر |

278 اختبارًا ناجحًا (`python -m pytest -q`).

## البدء السريع (للمطوّر)

```bash
# 1. فحص البيئة (على Termux أو أي Linux)
bash scripts/check_env.sh

# 2. إنشاء البيئة الافتراضية وتثبيت الاعتماديات
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

# 3. نسخ الإعدادات وتعبئتها (بدون أسرار حقيقية في الاختبارات)
cp .env.example .env
chmod 600 .env
```

## تشغيل بوت الـ Owner والمهام المجدولة

```bash
export MEDREP_DATA_DIR=./data
alembic upgrade head
python scripts/init_demo.py   # للتجربة فقط — بيانات وهمية
python scripts/run_owner_bot.py
```

`run_owner_bot.py` يشغّل شيئين معًا:
1. **بوت الـ Owner** (polling على Telegram).
2. **المهام المجدولة** (`app/jobs/runner.py`): كل دقيقة تُرسل التذكيرات
   المستحقة، وكل 30 دقيقة تُنشأ مهام المستقبل. التشغيل مكرر-آمن
   (idempotent): بدء ثانٍ يعيد المجدول الجاري بدل تشغيل نسخة مكررة،
   والإيقاف/إعادة التشغيل لا يكرران أي تذكير (الحالة في قاعدة البيانات).

> ملاحظة صريحة: الإرسال عبر Telegram **غير مربوط بعد** — المجدول يسجّل
> (LoggingNotifier) بدل الإرسال الحقيقي حتى يُختبر الإرسال لاحقًا.

الإعدادات المطلوبة في `.env` (لا ترسلها لأحد ولا تضعها في المحادثة):
- `TELEGRAM_OWNER_IDS` — رقم حسابك في Telegram (اعرفه من @userinfobot)
- `TELEGRAM_OWNER_BOT_TOKEN` — من @BotFather
- ثم اربط رقمك كمستخدم Owner في قاعدة الهوية (telegram_id يطابق رقمك)

بدون هذين الإعدادين يرفض البوت التشغيل عمدًا (fail-safe).

## القواعد الصارمة

1. لا أسرار حقيقية في الكود أو الاختبارات — كلها في `.env` (غير مرفوع).
2. عزل المكاتب بملفات قواعد بيانات منفصلة، لا بفلترة `office_id` فقط.
3. كل مرحلة تُختبر فعليًا بـ pytest قبل اعتبارها مكتملة.
4. لا حذف لأي مشروع موجود دون نسخة احتياطية وموافقة صريحة.

> ملاحظة بيئة الاختبار: على أجهزة يكون فيها /tmp صغيرًا (مثل 512MB)،
> نظّف `rm -rf /tmp/pytest-of-root` قبل التشغيل الكامل — كل تشغيل يترك
> ~45MB ملفات مؤقتة، وامتلاء /tmp يسبب أخطاء متقطعة ليست من الكود.
