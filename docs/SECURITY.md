# SECURITY.md — الأمان والصلاحيات

## 1. هوية الـ Owner

- تُعرَّف بـ `TELEGRAM_OWNER_IDS` (أرقام Telegram user ID) في `.env` — **خارج الكود**.
- `/start` لا يمنح أي صلاحية تلقائيًا. غير المعرّف = رفض صريح + تسجيل `ACCESS_DENIED`.
- آلية التهيئة الأولى: أمر `scripts/init_owner.py --telegram-id <ID>` يُشغَّل مرة
  واحدة بحضور المالك، ثم يُعطَّل.
- لا تُعرض توكنات أو مفاتيح أو كلمات مرور في المحادثة أبدًا.

## 2. نموذج الصلاحيات (يُطبَّق في الخادم، لا في الأزرار)

كل عملية تمرّ عبر `require_permission(actor, action, scope)`:

1. هوية المستخدم (من الجلسة/التوكن، لا من نص الرسالة).
2. دوره الحالي من `memberships` (active فقط).
3. الشركة والمكتب من العضوية — **لا** من اسم يكتبه المستخدم.
4. نطاق البيانات المسموح.
5. حالة الحساب والعضوية.

| الدور | النطاق |
|---|---|
| owner | كل الشركات والمكاتب (عبر مسار مدقق مكتب-مكتب) |
| manager | الشركة + المكاتب المسندة |
| supervisor | المكاتب والمندوبون المسندون |
| rep | بياناته وسجلاته فقط |

- لا صلاحية ضمنية: الرفض هو الافتراضي.
- الـ callback القديم يُتحقق من صلاحيته لحظة التنفيذ، لا لحظة العرض.

## 3. الأسرار

- كل الأسرار في `.env` بصلاحيات `600`. `.env.example` خالٍ من القيم.
- مفتاح تشفير لكل مكتب (`office_keys/{office_id}.key`) — منفصل عن النسخ الاحتياطية.
- لا أسرار في: الكود، الاختبارات، السجلات، رسائل Telegram، ملفات Excel.

## 4. سجل التدقيق

- كل عملية حساسة تُسجَّل: من، ماذا، متى (UTC)، النتيجة، السبب عند الرفض،
  `request_id`، وملخص قبل/بعد عند الحاجة.
- أحداث مثال: `OWNER_CREATED_COMPANY`، `DEDUCTION_APPLIED_DIRECTLY`،
  `DEDUCTION_APPROVED`، `VISIT_CORRECTED`، `EXPORT_CREATED`، `ACCESS_DENIED`.
- سجلات التدقيق: إلحاق فقط (append-only) — لا تعديل ولا حذف من الواجهات.
- لا كلمات مرور ولا مفاتيح داخل السجلات.

## 5. حماية العمليات المالية

- كل حركة مالية لها `uuid` فريد — تكرار الطلب لا يكرر الحركة.
- مقترح البوت (`proposed`) لا يغيّر الراتب حتى موافقة السوبرفايزر.
- الحركة المعتمدة لا تُعدَّل إلا بمسار تصحيح موثّق (حركة عكسية جديدة).
- إشعار المندوب بالخصم يتضمن: القيمة، السبب، الفترة، المنفِّذ.

## 6. حماية المدخلات والملفات

- Pydantic لكل مدخل؛ حدود صارمة لحجم الملفات المرفوعة وأنواعها.
- الملفات المرفوعة تُفحص ولا تُنفَّذ أبدًا.
- تصدير Excel: نطاق واحد (مكتب واحد) لكل ملف افتراضيًا + فحص الصلاحية.

## 7. النسخ الاحتياطية

- مشفّرة بـ Fernet بمفتاح المكتب؛ المفتاح **لا** يُحفظ بجانب النسخة.
- سجل `backup_records` + فحص `verified` + اختبار استعادة دوري.
- نسخة خارج الجهاز إلزامية (USB/سحابة) — نسخة الهاتف وحده لا تكفي.
